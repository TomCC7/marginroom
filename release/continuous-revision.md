# Continuous paragraph revisions — contract checkpoint

Accepted source HTML/overlay is authoritative; pending rewrites remain ordinary exact UTF-16 range records. A shared bounded grapheme diff produces separate hunks. No whole-paragraph pending lock.

## API (additive)
`GET /api/revision/:id?anchor=…` returns `{anchor,baseText,proposedText,version,sourceHash,records}`. Records use the existing public escaped shape plus `canUpdate`. Proposed text projects only caller-owned valid pending rewrites; foreign rewrites remain independently displayed/protected, not imported into the caller's canonical draft. Client keeps foreign saved markings outside draft; actual save overlap returns exact `existingId`. No identity tokens returned.

`POST /api/revision/:id` accepts `{anchor,version,sourceHash,proposedText,requestId,author}`; server derives actual hunks against authoritative accepted base and reconciles only authenticated caller-owned pending rewrites. Returns `{ok,snapshot}`. Caller identity never comes from author/JSON. Noop leaves records untouched. Version covers full paragraph pending/history state and source/overlay, with a monotonic database mutation epoch to reject ABA. Source-hash/version checked atomically. Same caller/request ID + identical payload returns committed receipt without reapplying; different payload rejects. Stale response retains client draft.

## Persistence checkpoint (before backend coding)
Additive idempotent migration: request receipt table, append-only rewrite-history table, monotonic paragraph mutation epochs (document-wide for source/accepted-overlay/access changes) maintained by SQLite triggers on suggestions/overlay changes. Existing suggestion rows/IDs/replies remain intact; no destructive migration. Existing NULL `request_caller` remains unproven legacy, never inferred from display name. New suggestions always record caller even without request ID. Removed hunks become `withdrawn` (not deleted); pending counts stay `status=open` only. Existing request payload remains immutable for legacy replay. Updated rows keep ID/time/replies and old/new content history. Split/merge association: retain only an unambiguous one-to-one overlapping old/new hunk; ambiguous split/merge retires old records with history and creates new IDs without moving/duplicating discussions. Unchanged hunks match first and retain exact IDs. Reconciliation first pins unchanged authored projected spans, then diffs the gaps; this prevents a new distant repeated letter from realigning an existing hunk. Epochs are paragraph-scoped; source/accepted-overlay/access changes invalidate the document. Document deletion is an explicit privacy purge of receipts/history, with numeric generation stamps retained to reject stale reuse.

Server resolves source anchors using the same leaf/hash/occurrence semantics as viewer; unsupported/generated content fails closed, not trusted client base. Existing single-range API and accept/rebase paths remain compatible. Stop writers and back up DB + source/identity before upgrade. Schema is additive and old code can read records, but rollback after new writes requires coordinated data restoration/reconciliation, not just file rollback.

## Native editing and limits
The existing 原位修改 entry fetches a fresh authenticated snapshot and opens the full paragraph with the caller's latest proposal. Cancel restores saved proposals; save sends one changeset, not multiple POSTs. Noneditable red deletion runs live at the original inline reading position; green CSS highlights cover only inserted runs. Both deletion and foreign-proposal decorations are excluded from editable body/payload. The editable/rich nodes survive native typing, undo and composition. Foreign saved proposals remain visible and protected; changing their actual range returns `range_overlap` with `existingId`. Unsupported generated/grouped content fails closed. Physical Safari/OS keyboard remains unverified. Native Chromium covers ordinary/static 1440/390; the ordinary renderer is a test-only compatibility path, not a restored user-facing mode.
