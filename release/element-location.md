# Persisted element identity v3

New element comments use `c3:<SHA256 scope>:<logical path>` (base36 components separated by dots; `self` for a uniquely identified element), bounded to 200 characters. It is carried in the existing opaque `anchor` string; no DB schema, HTTP API, dependency or permission change. All ordinary, static and interactive paths recognize c2/c3. All writers/readers must receive the six frontend assets together. Old clients do not understand c3 navigation.

An anonymous element is addressed within its nearest uniquely identified source ancestor (or review root). The complete canonical ordered scope is hashed, including full normalized text, element topology, source identity and src/alt/href. This distinguishes repeated siblings, nested repetitions and hidden responsive copies without choosing a first match. A changed scope refuses instead of allowing shifted paths to attach to another sibling. Conservative limitation: unrelated edits inside the same anonymous scope also invalidate its locator. A unique identified self target uses the complete subtree with identified child ordering canonicalized; moving independently identified children preserves its identity, while anonymous inline text order and subtree content changes remain guarded.

Review wrappers are transparent; inserted text/point controls/overlays are omitted. Classes, review attributes, style, visibility and live form properties are not identity inputs. The persisted contract does not depend on session WeakMaps. Positive bindings cannot switch to an in-session replacement object; source mutation during async hashing is refused. Missing lookups are not permanently cached, and the UI retains an explicit retry action and only clears its warning after an exact successful locate. Reveal completion is generation-gated, including cancellation versus genuine missing.
